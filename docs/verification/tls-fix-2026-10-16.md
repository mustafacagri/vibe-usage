# Claude / Cursor TLS düzeltmesi — 0.1.1

## Kök neden

Terminal `status`/`watch` ve Electron aynı `getJson` okuyucusunu kullanıyordu. Okuyucu varsayılan Node HTTPS agent'ına güveniyordu. Bu ortamda Node'un varsayılan CA listesi Windows'un güvendiği bütün sertifikaları içermediğinden iki sağlayıcı da `SELF_SIGNED_CERT_IN_CHAIN` ile başarısız oldu. Kimliksiz Windows HTTPS isteği aynı adrese TLS doğrulamasını geçerek HTTP 401 alırken, eski Node isteği TLS aşamasında durdu. Hata kimlik doğrulama veya kota tükenmesi değildi.

## Kalıcı değişiklik

`src/providers/tls-trust.cjs`, yalnız dış kota istekleri için özel bir HTTPS agent oluşturur. [Node'un resmi API'si](https://nodejs.org/download/release/v22.21.1/docs/api/tls.html#tlsgetcacertificatestype) üzerinden `default` ve `system` CA listelerini birleştirir. Node bu API ile Windows sertifika deposunu ve macOS sistem güvenini okuyabilir; davranış [Node ağ yapılandırma belgesinde](https://nodejs.org/learn/http/enterprise-network-configuration) açıklanır.

- `rejectUnauthorized: true` ve yerleşik `tls.checkServerIdentity` korunur.
- İşletim sistemi güven deposuna sertifika eklenmez; indirilen veya uygulamaya gömülü bir üretim CA paketi kullanılmaz.
- Global TLS policy, ortam değişkenleri ve başka uygulamaların ağ davranışı değişmez.
- Sertifika hatası ile okunamayan güven deposu ayrı, temizlenmiş kullanıcı mesajları üretir; ham hata/sertifika ayrıntıları gösterilmez.
- CLI runtime aralığı `^22.15.0 || >=24.0.0`; eski API'siz Node 22/23 sürümleri desteklenmez. Electron kendi runtime'ını içerir.
